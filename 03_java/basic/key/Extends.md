# ***Extends, 상속***
  
예를 들어 `ElectricCar` 와 `GasCar` 두 클래스가 있다고 생각해보자.  

그럼 두 클래스 모두 차이기 때문에 이동하는 기능이 있지만 연료의 충전 방식만 다르다.  

그렇다면 두 클래스를 이동 메서드가 있는 하나의 상위 클래스로 묶는다면 반복을 피할 수 있지 않을까?  

여기서 등장하는게 `상속`의 개념이다.  

- 용어
  - 부모 클래스 ( Super class ): 상속을 통해 자신의 필드와 메서드를 제공하는 클래스
  - 자식 클래스 ( Sub class ): 부모 클래스로부터 필드와 메서드를 상속받는 클래스

```java
public class Car {
    public void move() {
        System.out.println("차를 이동합니다,");
    }
}
```
```java
public class ElectricCar extends Car {
    public void charge() {
        System.out.println("충전합니다.");
    }
}
```
```java
public class GasCar extends Car {
    public void fillUp() {
        System.out.println("기름을 주유합니다.");
    }
}
```
이렇게 하면 `Car`를 상속받은 두 클래스 모두 `move` 메서드를 사용할 수 있고  
각자의 클래스 메서드인 `charge` 와 `fillup` 이 사용 가능하다.  

단 이 떄 부모클래스는 자식클래스의 메서드를 사용할 수 없다. `Car` 클래스는 `charge` 와 `fillUp` 을 사용하지 못한다.
  
그리고 다중 상속을 지원하는 파이썬과 달리 자바는 다중 상속을 지원하지 않는다. `단일 상속` 만 가능하다.
  
---

## 상속과 메모리 구조

부모 클래스가 있는 자식 클래스를 호출하게 되면 ( 인스턴스를 생성하면 ) 해당 메모리에는 부모의 클래스 정보도 담겨있다.
메서드를 사용해야하니 정보를 담고 있어야하는 것이다.
  
이렇게 한 메모리에 여러 클래스 정보가 있다면 객체를 통해 메서드나 필드를 호출 할 때 해당 객체의 타입과 같은 타입에서 
메서드나 필드를 찾는다. 해당 정보가 없다면 컴파일이 안된다.

---

## 상속과 메서드 오버라이딩
  
부모에게 상속 받은 기능을 자식이 재정의하는 것을 메서드 오버라이딩이라고 한다. 자식 클래스에서 부모 클래스의 메서드를 덮어 쓰는 것이다.
  
위에서 설명한 메모리 구조 부분에서 자식 클래스에 호출한 메서드가 없으면 부모 클래스에 가서 찾는다고 했는데,
같은 메서드를 자식 클래스에도 만들면 자식 클래스의 메서드를 사용하게 된다.

- 같은 메서드이지만 매개변수를 다르게 설정하는 오버로딩과는 다른 개념이다.

---

## super - 부모 참조
  
그런데 기껏 오버라이딩을 해도 같은 이름의 부모 클래스의 메서드를 사용해야할 때가 있다. 그럴 때는 어떻게 해야할까?  

`super` 키워드를 사용하면 된다. 같은 이름의 메서드가 있어도 `super` 키워드를 `this` 키워드 사용하듯이 앞에 붙이면
상위 클래스의 메서드를 사용할 수 있다.

---

## super - 생성자
  
위에서 상속관계의 클래스를 호출하면 한 메모리에 여러 클래스 정보가 들어간다 했는데, 그렇게 되려면 반드시 여러 클래스의
생성자가 호출되어야한다. 그래서 자식 클래스는 항상 부모 클래스의 생성자를 호출해야한다.
  
상속 관계에서 부모의 생성자를 호출할 때는 `super() // 기본 생성자는 생략 가능` 를 사용하면 된다. 
super() 를 사용하지 않으면 기본생성자를 호출하는 것이다.
