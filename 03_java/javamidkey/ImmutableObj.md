# ***Immutable Object***

## 기본형과 참조형의 공유
자바의 데이터 타입을 가장 크게 보면 기본형과 참조형으로 나눌 수 있다.
- 기본형(Primitive Type): 하나의 값을 여러 변수에서 절대 공유하지 않는다.
- 참조형(Reference Type): 하나의 객체를 참조값을 통해 여러 변수에서 공유할 수 있다.
  
이전에 학습한 내용이라 큰 무리 없이 이해할 수 있을 것이다.
  

## 공유 참조와 사이드 이펙트
사이드 이펙트는 프로그래밍에서 어떤 계산이 의도된 작업 외에 추가적인 효과를 일으키는 것을 맗한다.  
참조형 데이터의 특성으로 인해 다른 변수의 값도 변화하는 것도 사이드 이펙트이다.
  
그런데 여러 변수가 하나의 참조형 객체를 공유하는 것을 막을 방법이 없다.  
같은 객체를 다른 변수가 공유하기 때문에 발생하는 문제이니 공유를 막으면 되지만 공유를 막을 방법이 없다.  
그러면 다른 변수는 서로 다른 객체를 참조해야한다.
  

## 불변 객체 - 도입
사실 문제는 공유가 아니다. 공유된 객체 데이터의 **변경**이 문제이다.  
데이터가 변하지 않는다면 오히려 객체를 하나만 사용하는 것이 효율적이다. 그럼 객체의 필드 변경을 막아보자 ( 불변 객체 )
  
**도입**
```java
public class ImmutableAddress {
    
    private final String value;
    
    public ImmutableAddress(String string) {
        this.value = value;
    }
    
    public String getValue() {
        return value;
    }
    
    @Override
    public String toString() {
        return data;
    }
}
```
- 필드가 변경되면 안되기 때문에 `final` 선언
- 필드 변경 메서드인 setValue() 오버라이딩(x)
- 따라서 이 클래스는 생성자를 통해서만 값 설정이 가능하고 이후 값을 변경하는 게 불가능하다.

  
- **정리**
  - 불변이라는 단순한 제약을 사용해 사이드 이펙트를 막을 수 있다.
    - 객체의 공유 참조는 막을 수 없다. 그래서 필드 변경을 막으면 사이드 이펙트는 차단된다.
    - 불변 객체의 값을 변경할 수 없으니 변경하고 싶다면 변경하고 싶은 값을 갖는 새 불변 객체를 만들어야한다.

## 불변 객체 - 값 변경
불변 객체를 사용하지만 값을 변경하는 메서드가 필요하면 어떻게 해야할까?  
불변객체는 값이 변하면 안되고 변하지도 않기 때문에 새로운 값을 뱉는 메서드를 만들어야한다.
```java
public class ImmutableObj {
    private final int value;
    
    public ImmutableObj(int value) {
        this.value = value;
    }
    
    public ImmutableObj add(int addValue) {
        int result = value + addValue;
        return new ImmutableObj(result);
    }
    
    public int getValue() {
        return value;
    }
}
```
- add() 메서드가 핵심이다.
- 불변 객체의 값을 변경하는게 아니라 그 값을 이용해서 새로운 객체를 만든다.

```java
immutableObj obj1 = new ImmutableObj(10);
ImmutableObj obj2 = obj.add(20);
```
- obj1 == 10, obj2 == 30


### 참고 - withxxx()
불변 객체에서 값을 변경하는 경우 withxxx() 처럼 `with` 로 시작하는 경우가 많다.  
불변 객체의 메서드가 with 를 포함하는 경우 그 메서드는 jobs 를 수행한 뒤 새 인스턴스를 반환한다는 뜻이다.  
- with 는 관례처럼 사용되는데, 원본 객체의 상태가 유지되면서 변경사항을 새 인스턴스에 포함하는 과정을 표현한다.

## 정리
불변 객체가 중요한 이유는 자바에서 가장 많이 사용되는 `String` 클래스가 바로 불변 객체이기 때문이다. 뿐만 아니라 자바가 기본으로 제공하는
Integer, LocalData 등 수 많은 클래스가 불변으로 설계되어 있다.  
따라서 불변 객체를 이해해야 이런 기본 클래스도 제대로 이해할 수 있다.
  
**모든 클래스를 불변으로 만드는 것은 아니다.**  
우리가 만드는 대분의 클래스는 가변 클래스이다. 불변 클래스는 정말 특별한 상황에 만들어서 사용한다고 생각해도 된다.  
때로는 같은 기능을 하는 클래스를 하나는 불변으로 하나는 가변으로 각각 만드는 경우도 있다.
  
클래스를 불변으로 설계하는 이유는 더 많다.
- 캐시 안정성
- 멀티 쓰레드 안정성
- 엔티티의 값 타임 등
  
지금은 다 이해할 수 없지만 추후 자바를 배우다보면 마주칠 것이다. 지금은 불변 클래스가 어디에 사용되고, 어떻게 활용되는지 보다는
불변 클래스의 원리를 이해하는 정도면 충분하다.
