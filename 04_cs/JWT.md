# JWT, Json Web Token.

우선 `JWT` 는 말 그대로 Json 형식으로 된 Wen Token 이다! 이 친구를 이해하기 위해서는 우선 사용 목적을 알아야한다.

## 왜 쓰는거야 ?
JWT 는 주로 웹에서 **인증** 을 하기 위해 사용한다. 비유하자면 회사의 사원증 같은 것이다 !

회사원은 회사에서 무언가 하기 위해서는 사원증이 필요하다. 회사 들어갈 때, 출근 도장을 찍을 때, 구내 식당에서 밥을 먹을 때 등등,, 내가 그 회사의 일원이라는 걸 증명해야 그 회사에서 활동을 할 수가 있다.

JWT 도 똑같다 !

우리가 어떤 웹사이트에서 회원가입 ( 입사 ) 을 하고 웹 사이트의 API 를 이용 ( 사내 활동 ) 하기 위해서는 내가 이 사이트의 회원이라는 것을 증명해야한다 ! 이 때 우리는 JWT ( 사원증 ) 를 주고 받으며 이를 증명한다 .

엄밀히 말하자면 Token 을 주고 받으며 신분을 증명하고 JWT 는 그 Token 의 종류 중 하나이지만 우선 이렇게 이해해도 충분하다 !

## 발급은 ?
토큰의 발급은 로그인과 같이 진행된다. 회원가입을 하고 로그인을 하게 되면 Http ( 주로Header ) 에 토큰이 발행되는데 사용하는 데에 권한이 필요한 API 는 이 토큰을 주고 받으며 사용자 인증을 한다.

그 후 로그아웃을 하게 되면 이 토큰은 폐기되며 또 토큰을 발급 받은 후 만료시간 까지 **갱신**을 하지 않아도 폐기된다.

폐기된 토큰은 재사용이 불가능하고 다시 발급 받아야한다.

## 갱신 ?
만일 통신 중 토큰이 탈취되면 도용의 가능성이 생긴다. 그렇기 때문에 만일 도용되더라도 피해를 최소화 하기 위해 expired_time 을 정해둔다. 그런데 그러면 만료될 때마다 토큰을 다시 발급 받아야하는데 이는 클라이언트 입장에서 매우 귀찮다 !!

위 만료 시간이 30분인 사이트라면 사이트를 이용하며 30분이 지날 때마다 매 번 다시 로그인을 해야한다. ( 벌써 귀찮아 )

그래서 이를 돕기 위해 JWT 는 토큰을 두 종류로 나눠두었다. 첫 번째는 `Access Token`, 두 번째는 `Refresh Token` 이다.

### Access Token
Access token 은 지금까지 이야기 했던 토큰의 개념과 같다. 위에서 얘기한 토큰은 모두 이 Access Token 에 관한 이야기이다.

로그인을 통해 발급 받고 API 사용을 위해 서버와 주고 받는, 신분 증명을 위한 토큰이다.

### Refresh Token
Refresh Token 은 이름에서 느낌이 오겠지만 바로 **갱신**을 위한 토큰이다. 만료된 Access Token 을 다시 살려주는 토큰이다 ! 어쩌면 갱신보다는 재발급이 더 적절한 표현일 수 있겠다.

비유를 하자면 Access Token 은 사원증 이고 Refresh Token 은 사원증 발급 신청서 이다.

사원증을 분실하거나 문제가 생기면 발급 신청서를 제출해서 다시 재발급 받을 수 있다. 하지만 신청서 만으로는 신분의 증명이 불가능하다. Token 또한 마찬가지이다. Access Token 이 만료되면 서버는 Refresh Token 을 먼저 요구한다. Refresh Token 이 클라이언트에게 있다면 이를 확인하여 Access Token 을 다시 발행하고, 없거나 이마저도 만료되었다면 클라이언트는 다시 로그인을 해서 토큰을 다시 발급 받아야한다..

## Access.. Refresh.. 잠깐, 뭔가 이상한데 ?
뭔가 이상하다. 토큰 탈취를 막기 위해 Access 에 만료시간을 걸어두었는데 이게 만료되면 Refresh 로 재발급을 받을 수 있다고? 그럼 Refresh 를 탈취 당하면 위험하잖아? 결국 그냥 똑같은거 아니야?

라고 생각할 수 있다! 내가 그랬으니까.

그래서 이를 막기 위해 Refresh 토큰은 서버에서도 관리한다. 클라이언트가 제시하는 Refresh 와 서버가 관리하는 Refresh 가 일치하지 않으면 그 접근은 거부된다.

### 안이상하다고?
그럴리가 없다 !

1. 클라이언트 로그인
2. 제 3자의 토큰 탈취
3. 클라이언트 로그아웃
4. 탈취범이 클라이언트의 토큰을 이용해 API 사용

이게 가능하면 안된다! 클라이언트가 로그아웃을 하면 토큰은 비활성화가 되어 4번이 불가능해져야한다.

그래서 서버에서는 클라이언트의 토큰과 서버의 토큰을 교차검증 하는 것이다. 클라이언트가 로그아웃을 하면 서버의 토큰을 폐기하고 이후 같은 토큰이 제시되어도 이미 폐기된 토큰이기에 접근이 거부된다.

Access 토큰을 탈취당하면 이를 막기가 매우 까다롭지만 그래도 만료시간이 지나면 토큰은 저절로 무력화된다. Refresh 토큰이 탈취 당하더라도 사용자가 로그아웃을 하는 순간 토큰이 무력화된다.

## 한 줄 요 약
JWT 는 사용자 인증을 하기 위해 사용자와 서버가 주고 받는 Json 객체 (토큰) !
