# 프로토콜, Protocol

해당 절에서는 통신과정에서 정보를 올바르게 주고 받기 위해 합의된 규칙이나 방법을 의미하는 **프로토콜**, 통신이 일어나는 구조를 계층화한 **네트워크 참조 모델**, 통신 과정에서 이루어지는 **캡슐화 (역 캡슐화)**를 학습한다.
  
현대 인터넷은 호스트 간 패킷을 교환하는 방식으로 대부분 **패킷 교환** 방식을 사용한다. 원격에 있는 사용자에게 패킷을 보내는 과정을 택배에 비유해보자.
- 선물할 책 (페이로드) 를 택배 상자(패킷)에 담는다.
- 배송 주소 등 택배 기사가 읽을 메시지(헤더)를 작성하고 첨부한다.
- 택배 기사(네트워크 장비) 를 통해 발송한다.  
또한 원격 사용자가 받아서 책을 읽기 위해서는 기본적으로 언어가 통해야한다.
  
네트워크에도 이 언어와 비슷한 개념이 있고 이게 바로 **프로토콜**이다. **프로토콜, Protocol**은 노드 간에 정보를 올바르게 주고 받기 위해 합의된 구칙이나 방법을 의미한다.
  
즉, 서로 다른 통신 장치들이 정보를 주고 받으려면 프로토콜이 통해야한다. 다음은 예시이다.
  
> IP는 패킷을 수신지까지 전달하기 위해 사용되는 프로토콜이다.
  
이 문장에서 **IP** 는 프로토콜이다. IP라는 규칙으로 정보를 주고받음으로써 패킷을 수신지까지 올바르게 전달할 수 있다.
  
> ARP는 192.168.1.1과 같은 형태의 'IP 주소'를 A1:B2:C3:D4:E5:F6 과 같은 형태의 'MAC 주소'로 대응하기 위해 사용되는 프로토콜이다.
  
위 문장에서 **ARP**는 프로토콜이다. IP 주소를 MAC 주소로 대응하기 위해서는 ARP 규칙이 필요함을 의미한다.
  
> HTTPS 는 HTTP에 비해 보안상 더 안전한 프로토콜이다.
  
이 문장에서 **HTTPS**와 **HTTP** 는 모두 프로토콜이다. HTTP라는 규칙으로 정보를 주고 받는 것보다 HTTPS 가 더 안전함을 의미한다.
  
> TCP는 UDP에 비해 일반적으로 느리지만 신뢰성이 높은 프로토콜이다.
  
위 문장에서 **TCP**와 **UDP**는 모두 프로토콜이다.
  
예시처럼 모든 프로토콜에는 저마다의 **목적**과 **특징**이 존재한다. 즉, 프로토콜마다 패킷의 헤더 내용이 달라질 수 있다. ( 헤더가 없는 프로토콜 또한 존재한다. )
  
# 네트워크 참조 모델
네트워크로 메시지를 송수신하는 것은 택배를 주고 받는 것과 유사하다고 했는데 이 과정을 세밀히 나누어 보면 다음과 같다.
1. 선물할 책을 준비한다.
2. 책이 상하지 않도록 책을 포장한다.
3. 포장된 책을 상자에 넣는다.
4. 상자를 밀봉한다.
5. 송장을 붙인다.
6. 기사에게 전달한다.  
받는 과정은 다음과 같다.
1. 기사로부터 받는다.
2. 송장을 제거한다.
3. 상자를 연다.
4. 책을 꺼낸다.
5. 포장을 뜯는다.
6. 책을 확인한다.
  
이렇게 정형화된 순서가 있음을 확인할 수 있다.
  
이런 일련의 과정을 계층으로 표현할 수 있다. 이렇게 계층화된 구조를 **네트워크 참조 모델, Network Reference Model**이라고 한다. 계층으로 표현하기 때문에 **네트워크 계층 모델**이라고 부르기도 한다.
  
이렇게 계층으로 나누는 이유는 크게 두가지가 있다.
  
**첫째, 네트워크 구성과 설계가 용이하다.**  
계층 별 수행할 역할이 정해지므로 이에 맞게 프로토콜과 네트워크 장비를 계층별로 구성할 수 있다. 모든 프로토콜이나 네트워크 장비가 참조 모델과 완벽히 들어맞는 것은 아니지만 충분한 가이드라인 역할을 수행할 수 있다.
  
**둘쨰, 네트워크 문제 진단과 해결이 용이하다.**  
통신과정에서 문제가 발생해도 문제의 원인을 계층별로 진단하기 수월하다.
  
## OSI 모델
OSI 모델은 국제 표준화 기구에서 만든 네트워크 참조 모델로 계층을 7개로 나눈다.
1. 물리 계층
OSI 모델의 최하단 계층으로 비트 신호를 주고 받는 계층이다. 가장 근원적 통신이 이루어지는 계층이라 할 수 있다.
2. 데이터 링크 계층
네트워크 내 주변 장치 간의 정보를 올바르게 주고받기 위한 계층이다. 물리 계층을 통한 정보에 오류가 없는지 확인하고 네트워크 내 송수신지를 특정한다. 때로는 전송 과정에서 발생할 수 있는 충돌 문제를 해결하는 계층이기도 하다.
3. 네트워크 계층
메시지를 수신지까지 전달하는 계층이다. 데이터 링크 계층에서 로컬간의 통신이 이루어진다면 네트워크 계층은 리모트간의 통신이 이루어진다. IP 주소를 통해 통신하고자 하는 수신지 호스트와 네트워크를 식별하고 경로를 설정한다.
4. 전송 계층
신뢰성 있고 안정성 있는 전송을 해야 할 때 필요한 계층이다. 패킷이 정상적으로 보내졌는지, 중간에 유실된 정보는 없는지, 여러 개의 패킷을 보낼 때 순서가 뒤바뀐 것은 없는지 등을 확인해야할 때가 있는데 이떄 전송 계층에서 패킷의 흐름을 제어하거나 전송 오류를 점검한다. 이 외에도 포트라는 정보를 통해 실행 중인 프로그램의 식별을 하기도 한다.
5. 세션 계층
이름 그대로 세션을 관리하는 계층이다. **세션, Session**이라는 용어는 다양한 상황에서 폭넓게 사용되지만 일반적으로 통신을 주고받는 호스트의 응용 프로그램 간 연결 상태를 의미한다. 세션 계층에서는 이러한 연결을 만들거나 유지하고 종료되었을 때 끊는 역할을 담당한다.
6. 표현 계층
번역기와 같은 역할을 하는 계층이다. 자연어를 프로그램어로 바꾸거나 압축, 암호화 같은 작업이 이루어진다.
7. 응용 계층
OSI 모델 최상단의 계층으로 사용자 및 사용자가 이용하는 응용 프로그램과 가장 밀접히 맞닿아 있는 계층이다. 사용자에게 다양한 네트워크 서비스를 제공하는 계층이다, ( 웹 브라우저 페이지, 이메일 송수신 등등 )

## TCP/IP 모델
OSI 모델은 주로 네트워크를 이론적으로 기술하고 이해할 때 사용하는 반면에 **TCP/IP** 모델은 이론 보다는 구현에 중점을 둔 네트워크 참조 모델이다. '이상적 설계' vs '실용적 구현'  
TCP/IP 모델은 TCP/IP 4계층, 인터넷 프로토콜 스위트, TCP/IP 프로토콜 스택이라고도 부르며 TCP와 IP는 프로토콜의 이름이며 IP는 **Internet Protocol**의 약자이다.  
이 두 프로토콜이 오늘날 네트워크 구현의 핵심이기 때문에 이런 이름이 붙었다.
  
TCP/IP 모델은 최하위 계층에서 최상위 계층순으로 각각 네트워크 액세스 계층, 인터넷 계층, 전송 계층, 응용 계층으로 이루어진다.

1. 네트워크 액세스 계층
**링크 계층, Link Layer** 또는 **네트워크 인터페이스 계층, Network Interface Layer**라고도 부른다. 이 계층은 OSI 모델의 데이터 링크 계층과 유사하다.  
  
2. 인터넷 계층
OSI 모델에서의 네트워크 계층과 유사하다.

3. 전송 계층
OSI 모델에서의 전송 계층과 유사하다.
  
4. 응용 계층
OSI 모델의 세션 계층, 표현 계층, 응용 계층을 합친 것과 유사하다.

# 캡슐화와 역캡슐화
지금까지 프로톨과 네트워크 참조 모델을 토대로 실제로 포캣이 어떻게 송수신 되는지 확인했다.
  
패킷은 송신 과정에서 **캡슐화**가 이루어지고, 수신 과정에서 **역캡슐화**가 이루어진다.
  
네트워크 참조 모델에서 본 택배 예시를 다시 보면 송신자 입장에서 택배는 가장 높은 계층에서 가장 낮은 계층으로, 이후 수신자 입장에서는 가장 낮은 계층에서 가장 높은 계층으로 이동한다. 이는 네트워크 참조 모델에서도 동일하다.
  
## 캡슐화
어떤 정보를 송신할 때 각 계층에서는 상위 계층으로부터 내려받은 패킷을 페이로드로 삼아 프로토콜에 걸맞은 헤더( 또는 트레일러 ) 를 덧붙인 후 하위 계층으로 전달한다. 즉 한 단계 아래 계층은 바로 위 계층으로부터 받은 패킷에 헤더 및 트레일러를 추가하는 것이다. 이 과정을 **캡슐화, Encapsulation**이라고 하고 또는 영문 그대로 **인캡슐레이션**이라고도 한다.  
계층이 내려갈 수록 점점 덩치가 커진다고 생각하면 된다. (헤더 또는 트레일러가 계속 추가되기 때문)

## 역캡슐화
수신과정에서는 송신의 캡슐화 과정에서 붙였던 헤더 또는 트레일러를 각 계층에서 확인한 뒤 제거하는 **역캡슐화, Decapsulation** 과정을 거친다.

# PDU
각 계층에서 송수신되는 메시지의 단위를 **PDU, Protocol Data Unit** 이라고 한다. 상위 계층에서 전달받은 데이터에 현재 계층의 프로토콜 헤더 또는 트레일러를 추가하면 현재 계층의 PDU가 된다.
  
PDU는 주로 전송 계층 이하의 메시지를 구분하기 위해 사용한다. OSI 모델의 각 계층에서의 PDU를 정리해보면 다음과 같다.
![PDU](/04_cs/혼자%20공부하는%20네트워크/properties/PDU.png)
  
PDU는 주로 전송계층 이하의 메시지를 구분하기 위해 사용하고 전송 계층의 상위 계층에서는 일반적으로 데이터, 메시지라고 지칭하는 경우가 많다.
  
표를 보면 네트워크 계층의 PDU가 '패킷'이라고 되어있는데 지금까지 거론한 패킷과는 다른 대상을 지칭한다. 이는 송수신의 단위를 이야기하는 것이고 이 책에서는 **IP 패킷** 이라고 지칭하겠다.

# 트래픽과 네트워크 성능 지표
네트워크에서 자주 사용되는 용어 중 네트워크 트래픽이라는 말이 있다. **트래픽, Traffic**이란 네트워크 내의 정보량을 의미한다. 라우터(네트워크 장비)에 트래픽이 몰린다. 서버(호스트)의 트래픽을 분산한다. 라는 표현에 사용되는 트래픽이 이것이다.
  
특정 노드에 트래픽이 몰리는 것은 처리해야할 정보의 양이 많음을 의미하고 이 경우 해당 노드에 **과부하, Overhead**가 생길 수 있다. 컴퓨터에서 CPU에 부하가 걸리면 성능이 저하되는 것 같이 노드도 과부하가 걸리면 성능이 저하될 수 있다.
  
이 '성능'을 평가하는 지표는 다음과 같은 세 가지가 있다.
1. **처리율, Throughput**
영문 그대로 쓰루풋이라고 표현하기도 하는 처리율은 단위 시간당 네트워크를 통해 실제 전송되는 정보량을 의미한다. 일반적으로 **bps, Mbps, Gbps** 단위로 표현한다. 순서대로 비트, 메가비트, 기가비트를 의미하고 때로는 초당 패킷 수를 표현하기 위해 **pps** 단위를 사용하기도 한다. (packets per second) 처리율은 다른 두 지표에 비해 실시간성이 강조된 지표로 현재 트래픽 양을 판단하기 위해 사용된다.

2. **대역폭, Bandwidth**
대역폭은 신호 처리 영역에서의 정의와 네트워크 성능 측정 영역에서의 정의가 다르다. 전자는 주파수의 범위를 의미하지만 후자는 단위 시간 동안 통신 매체를 통해 송수신할 수 있는 최대 정보량을 의미한다. 처리율과 같은 단위를 사용하고 통신 매체가 높은 대역폭을 가지고 있다는 말은 많은 정보를 송수신할 능력이 있음을 의미한다.
  
3. **패킷 손실, Packet loss**
패킷 손실, 패킷 로스는 말 그대로 패킷이 손실된 상황을 의미한다. 높은 트래픽으로 인해 노드에 부하가 걸리거나 네트워크상에 예기치 못한 장애가 발생해서 패킷을 처리하지 못하면 패킷 손실이 발생할 수 있다. 이를 표현할 때는 전체 패킷에서 손실된 패킷의 백분위를 사용하는 경우가 많다.
